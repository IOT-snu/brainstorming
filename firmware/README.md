# FOA firmware and testbed tools

Everything here was built and checked before the boards arrived. What is verified now and what
still needs the hardware is listed at the end.

## Layout

| Path | What it is |
|---|---|
| `esp32_foa/foa_core.c/.h` | Detector, signature-free proposal, geometric median, FOA step, 68-byte authenticated frames. Portable C99, no heap. Mirrors `experiments/foa/detector.py` and `foa_rule.py`. |
| `esp32_foa/foa_sha256.c/.h` | SHA-256 and HMAC-SHA256 (FIPS 180-4, RFC 2104), checked against RFC 4231. |
| `esp32_foa/foa_features.c/.h` | Kitsune-style damped statistics of the node's own traffic (60 features), projected into the fleet's shared 10-D space. |
| `esp32_foa/esp32_foa.ino` | The node: telemetry over UDP, feature sampling, on-device calibration, one learning cycle per 200 samples, ESP-NOW gossip, CSV log over Serial. |
| `esp32_foa/foa_config.h` | Generated by `fit_calibration.py`: node settings, per-node keys, shared basis. Currently a placeholder basis and development keys. |
| `ina219_monitor/ina219_monitor.ino` | The fifth ESP32: reads the INA219 at about 1 kHz and streams power samples. |
| `footprint_baseline/` | Same Wi-Fi and ESP-NOW code without FOA, to measure FOA's own flash and RAM cost. |
| `host_test.c`, `make_vectors.py` | Equivalence test of the C core against the Python reference, plus host timing. |
| `fit_calibration.py` | Fits the shared basis from logged clean traffic and writes `foa_config.h`. |
| `laptop/poisoner.py` | Testbed attacker: steers one node's incoming traffic (boiling-frog ramp, pulsing, decoy bursts, flood). |
| `laptop/collector.py` | Captures every node's Serial log and the telemetry, then summarises latency, peers, bytes and energy per cycle. |

## Build and test (no hardware needed)

```bash
python3 firmware/make_vectors.py
```
```bash
cc -O2 -std=c99 -Wall -Wextra -o firmware/host_test firmware/host_test.c firmware/esp32_foa/foa_core.c firmware/esp32_foa/foa_sha256.c -lm
```
```bash
./firmware/host_test firmware/vectors.bin
```
```bash
arduino-cli compile --fqbn esp32:esp32:esp32 firmware/esp32_foa
```

Results on 24 Oct 2026 (Arduino-ESP32 core 3.3.12, ESP32 Dev Module):

| Check | Result |
|---|---|
| C proposal vs Python, 480 recorded cycles | 0 mismatches, worst relative error 8.3e-4 (float32 vs float64) |
| C FOA step vs Python, 480 cycles (130 with fewer than 2 peers) | 0 mismatches, worst relative error 4.5e-5 |
| Frames packed in C vs Python | 32/32 byte-identical |
| Tampered frames accepted | 0 of 16,896 single-bit flips, 32 wrong keys, 32 stale cycles |
| HMAC-SHA256, RFC 4231 test case 2 | pass |
| Node sketch, full build | 913,688 B flash (69%), 61,064 B static RAM (18%) |
| Same sketch without FOA | 893,284 B flash, 48,928 B static RAM |
| FOA's own cost | about 20 KB flash, about 12 KB static RAM (8 KB is the 200-sample batch), plus 53 KB heap during calibration only, freed after |
| Energy monitor sketch | 294,008 B flash, 23,500 B static RAM |

## Hardware day: what to do, in order

1. **Wire the energy monitor** as in `circuit/` (INA219 high-side in the measured node's 5 V line).
2. **Fix the router to channel 6** (ESP-NOW and Wi-Fi must share a channel). Put the SSID and password in `foa_config.h` locally. Never commit them.
3. **Flash four nodes** with `NODE_ID` 0 to 3: `arduino-cli compile --fqbn esp32:esp32:esp32 --build-property "build.extra_flags=-DNODE_ID=1 -DCALIB_LOG" firmware/esp32_foa`, then `arduino-cli upload -p <port> ...`.
4. **Calibration run (clean, 20 minutes):** run `laptop/collector.py logs/calib --serial <ports>`, then `python3 firmware/fit_calibration.py --from-logs logs/calib/*.log`. This writes the real shared basis and fresh keys. Reflash without `-DCALIB_LOG`.
5. **Idle baseline (10 minutes):** collector running, no attacker. This gives per-cycle latency and the idle power baseline.
6. **Honest common drift:** change the router setting every node shares (for example its traffic shaping or the collector's address), or raise every node's telemetry rate. This is the real drift the simulations could only inject.
7. **Poisoning:** `python3 firmware/laptop/poisoner.py --node <ip of node 0> --mode boiling --share 0.3 --ramp 1800`, then `--mode flood` to check the attack is still detected.
8. **Freeze attack:** `--mode decoy --duration 600`. FOA nodes should not change their trajectory.
9. **Summarise:** `python3 firmware/laptop/collector.py logs/<run> --summarise` prints latency, peers per cycle, bytes and mJ per cycle per node.

## What still needs the hardware

- Real per-cycle latency, energy per learning cycle and ESP-NOW loss on the boards (the sketch already logs everything needed; the paper currently reports host timings and datasheet-based estimates, labelled as such).
- The fleet-shared basis fitted on the testbed's own traffic (`fit_calibration.py --from-logs`).
- A real, not injected, common drift event across the nodes.
